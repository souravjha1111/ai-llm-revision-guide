Tokenization

How raw text becomes the numeric sequence an LLM can process.

01 / DEFINITION

What is a token?

A token is a unit of text chosen by a tokenizer. It can be a whole word, part of a word, punctuation, whitespace, or a byte-level piece.

02 / DON'T CONFUSE

Token ≠ ID ≠ embedding

  • Token: text piece, e.g. cat
  • Token ID: integer assigned to that piece
  • Embedding: learned vector looked up using the ID
03 / WHY SUBWORDS

Why not one token per word?

A word-only vocabulary becomes huge and struggles with unseen words. Character-only splitting creates long sequences. Subwords balance vocabulary size and sequence length.

04 / BPE

Byte Pair Encoding

Repeatedly merge frequent adjacent units into a larger unit during tokenizer training.

VOCABULARYA finite lookup table

Each token piece has an integer ID. IDs are labels, not semantic scores; ID 500 is not “more meaningful” than ID 20.

SPECIAL TOKENSStructure & control markers

They can mark message boundaries, end-of-sequence, padding, unknown input, or roles in a chat format.

INTERVIEW QUESTION BANK

Tokenization — questions & answers

Open a question to revise its answer. These cover fundamentals, design choices, model behaviour, practical debugging, and common interview follow-ups.

30 QUESTIONS
A · Core concepts
1. What is tokenization, and why do LLMs need it?

Tokenization converts raw text into a sequence of discrete token pieces, then maps each piece to an integer ID. Neural networks operate on numbers, so tokenization provides a finite, consistent input representation before IDs are converted into embedding vectors.

Flow: text → token pieces → token IDs → embedding vectors.

2. What exactly is a token?

A token is a unit defined by a tokenizer. It may be a complete word, a subword, punctuation, whitespace, or a byte-derived piece. It is not necessarily a word or a character.

3. What is the difference between a token, token ID, and embedding?
  • Token: the piece of text, such as cat.
  • Token ID: the integer assigned to that piece by a particular vocabulary.
  • Embedding: a learned dense vector associated with the ID.

The ID is a lookup key, not the vector and not a measure of meaning.

4. Is one word always one token?

No. A common word may be one token, while a rare or morphologically complex word may split into several subwords. Even familiar words can split differently across tokenizers.

5. Why not use one token per word?

A word-level vocabulary would need an enormous number of entries, would struggle with names, misspellings and unseen words, and would need an unknown-word fallback. Subword vocabularies reuse pieces to represent both common and novel words with a manageable vocabulary.

6. Why not use one token per character?

Character-level tokenization has a small vocabulary and handles unseen words, but sequences become much longer. Longer sequences increase compute and memory costs, and make long-range relationships more expensive to model. Subwords are a practical compromise.

7. What is a tokenizer vocabulary?

It is the finite mapping between token pieces and integer IDs, often with additional metadata for special tokens. A vocabulary defines which pieces can be emitted directly; a word not present as a whole token can still be represented by multiple available pieces.

8. Do token IDs have an inherent order or semantic meaning?

No. IDs are categorical labels used to index embedding rows. ID 500 is not more meaningful, frequent, or similar to ID 501 than to ID 20. The learned embedding vectors carry the model's learned representation.

B · Algorithms and tokenizer design
9. What is Byte Pair Encoding (BPE)?

BPE starts from small units (commonly bytes or characters, depending on the variant) and repeatedly merges frequent adjacent pairs during tokenizer training. The learned merge rules are then applied in order to segment new input. Frequent sequences tend to become larger reusable tokens.

10. Explain BPE with a simple example.

Imagine the units l and o often occur together. Training may learn l + o → lo, and later merge lo + w → low. This is only an illustration; actual merges depend on corpus statistics and the tokenizer's initial units.

11. Is BPE the same as WordPiece or Unigram tokenization?

No. They are different subword-tokenization approaches. BPE learns a sequence of pair merges; WordPiece chooses pieces using a likelihood-oriented objective and greedy segmentation; Unigram starts with a larger candidate vocabulary and prunes pieces according to a probabilistic model. Exact implementations vary.

12. What is byte-level BPE?

It represents input through byte-level base units before applying merge rules. This gives broad coverage of arbitrary text and avoids needing a separate unknown token for every unseen character. The trade-off is that some Unicode characters may require multiple bytes and can look unintuitive when split.

13. How is a tokenizer trained?

Typically, a large representative text corpus is normalized or preprocessed, split into initial units, and used to learn a vocabulary and segmentation rules (or a probabilistic vocabulary). The resulting tokenizer files are fixed and reused at inference. Tokenizer training is separate from training the neural network weights, though both are designed to work together.

14. What factors influence vocabulary size?

Language and domain coverage, corpus size and diversity, desired sequence lengths, memory budget for embedding/output matrices, and model architecture all matter. A larger vocabulary can reduce token count for familiar text but increases parameters and can make rare pieces poorly represented.

15. What does an unknown token (UNK) do?

It is a fallback symbol used by tokenizers that cannot represent an input unit with their vocabulary. Byte-level approaches can often represent arbitrary byte sequences instead, reducing reliance on UNK. Not every modern tokenizer uses an unknown token in the same way.

C · Model input, context and cost
16. What happens after tokenization?

The token IDs index an embedding table to produce vectors. Positional information is incorporated by the model's positional mechanism, and the resulting sequence is processed by the network. During generation, predicted token IDs are decoded back into text by the tokenizer.

17. What is the difference between a tokenizer vocabulary and an embedding table?

The vocabulary maps token pieces to IDs. The embedding table is a learned matrix whose rows are vectors indexed by those IDs. They are related by indexing, but one is a symbolic mapping and the other is model parameters.

18. Why does tokenization affect the context window?

Context limits are measured in tokens, not words or characters. If a tokenizer splits a passage into more tokens, that passage consumes more of the model's available context. System prompts, chat formatting and tool outputs also consume tokens.

19. How does tokenization affect latency and inference cost?

More tokens generally mean more input processing and a longer sequence to generate. Attention-related compute and KV-cache memory often grow with sequence length, so token count can affect latency, throughput, memory, and usage-based billing. The exact cost depends on the architecture and serving implementation.

20. Why can the same sentence have different token counts in two models?

Models can use different tokenizer algorithms, vocabularies, training corpora, normalization rules, and special-token conventions. Token counts are therefore tokenizer-specific; never assume a count from one model applies to another.

21. Can a tokenizer be changed after a model is trained?

Not safely as a drop-in replacement. The model's embedding and output rows are tied to the original token IDs and meanings. Changing token-to-ID assignments changes what those rows represent. A compatible extension or migration requires carefully mapping or training embeddings and often additional model training.

22. Are input tokenization and output detokenization exact inverses?

They are designed to round-trip ordinary text as closely as possible, but normalization, whitespace handling, invalid byte sequences, and special-token treatment can make exact round-tripping non-trivial. Special tokens may be decoded visibly or skipped depending on the API options.

D · Edge cases and practical engineering
23. Why do emojis sometimes become multiple tokens?

Many emojis are Unicode sequences, sometimes combining multiple code points with variation selectors, skin-tone modifiers, or zero-width joiners. A tokenizer may represent their underlying bytes or subpieces separately. One visible glyph does not imply one code point or one token.

24. Why can Hindi or other non-English text use more tokens?

It depends on how well the tokenizer's vocabulary covers that language and script. If common words or character sequences are poorly represented, they split into more pieces. Unicode encoding and byte-level handling also influence segmentation. This is not a universal rule: a multilingual tokenizer may handle a language efficiently.

25. Why can code tokenize differently from natural language?

Code contains punctuation, operators, indentation, identifiers, paths, and repeated syntax patterns. Tokenizers may split identifiers and symbols into several pieces. This affects prompt budgets and can make code-heavy contexts consume many tokens.

26. Do spaces and newlines count as tokens?

They can. Some tokenizers attach leading spaces to words, represent whitespace as part of a token, or create dedicated newline/whitespace pieces. Never assume whitespace is discarded or costs zero tokens.

27. What are special tokens? Give examples.

Special tokens are reserved IDs used for structure or control, such as beginning/end of sequence, padding, unknown input, or chat message boundaries and role markers. Their visible spellings are often human-readable representations of dedicated IDs. The exact set is model- and format-specific.

28. What is the difference between EOS, padding, and a chat end-of-turn marker?

EOS commonly signals sequence termination. Padding fills shorter examples to a common batch length and is usually masked from attention/loss as appropriate. A chat end-of-turn marker signals that a message or assistant turn is complete; some chat formats distinguish this from ending the entire assistant interaction or handing control to a tool.

29. How would you debug a surprising token count in production?

First verify the exact model and tokenizer version, then inspect the actual serialized input (including system prompts, chat templates, tool schemas, whitespace, and special tokens). Print token pieces and IDs, compare normalization and truncation settings, and reproduce with the same tokenizer library/version. Do not estimate from word count.

30. How would you choose a tokenizer for a multilingual or code-heavy product?

Evaluate candidate tokenizers on representative, permission-safe samples from every target language and content type. Compare tokens per character/byte, sequence length, coverage, fragmentation of important terms, and downstream model quality—not just vocabulary size. Also measure context usage, latency, cost, and compatibility with the model's training setup.

Strong interview answer pattern: define the concept → explain why the design exists → walk through a concrete example → state the trade-off or failure mode. Avoid claiming every tokenizer uses BPE or that one word equals one token.

START HERE · IMPORTANT DISTINCTION
Notice that supervised, unsupervised, self-supervised and reinforcement learning are learning approaches. CNN, RNN and Transformer are architectures. Regression, classification, ranking and generation are tasks. These concepts overlap; they are not competing labels for a model.

Think of these as three separate questions: How does it learn? (learning approach), what kind of model is it? (architecture or model family), and what is it doing? (task). A single system can have one answer from each axis—or several training stages with different approaches.

Example: An LLM can use a Transformer architecture, be pretrained with self-supervised next-token prediction, instruction-tuned with supervised examples, and then preference-aligned. Its task at runtime may be generation, summarization, classification, or question answering.

Types of Machine Learning

The different ways a model can learn from data or interaction — and how these approaches relate to deep learning and generative AI.

Covered in session
FIRST: KEEP THE TAXONOMIES SEPARATE
Learning paradigmHow feedback or training signal is obtainedSupervised · Unsupervised · Self-supervised · Semi-supervised · Reinforcement
Model / technique familyHow patterns are represented or learnedTraditional ML · Deep learning · Transfer learning
Task / outputWhat the system is asked to doRegression · Classification · Clustering · Generation

These are different classification axes, not mutually exclusive boxes. For example, an LLM is a deep-learning model trained largely with self-supervised learning to perform generative tasks.

01 / LABELED DATA

Supervised learning

Learns from labeled examples: each training input is paired with a target answer. The model learns a mapping from input to output.

Tasks: regression (predict a number) and classification (predict a category).

Example: predict house price from size, location and other features.

02 / NO TARGET LABELS

Unsupervised learning

Finds structure or useful representations in data without explicit target labels.

Tasks: clustering, dimensionality reduction, density estimation and some anomaly-detection approaches.

Example: group customers by purchasing patterns using k-means.

03 / LABELS CREATED FROM DATA

Self-supervised learning

Creates its own training targets from the input data. It is often described as supervised-style optimization with automatically derived labels.

Example: an LLM predicts the next token from preceding tokens. No human needs to label the next word for every training example.

04 / MIXED LABEL AVAILABILITY

Semi-supervised learning

Uses a small labeled dataset together with a much larger unlabeled dataset. The unlabeled data can improve learning when labels are expensive.

Example: train an image classifier with 2,000 labeled images and 100,000 unlabeled images.

05 / REWARDS FROM INTERACTION

Reinforcement learning (RL)

An agent interacts with an environment, takes actions, observes outcomes and receives rewards or penalties. It learns a policy to maximize cumulative reward over time.

Example: an agent learns to play a game through repeated attempts and feedback.

06 / REUSE KNOWLEDGE

Transfer learning

Reuses knowledge learned on one task or dataset for a related task. A pretrained model is adapted rather than trained from scratch.

Example: fine-tune a pretrained vision model for defect detection in a factory.

07 / CONTINUOUS UPDATES

Online learning

Updates a model incrementally as new examples arrive, rather than waiting for a full offline retraining cycle. Useful when data distributions change or fresh feedback matters.

Trade-off: monitor drift, noisy feedback and catastrophic forgetting.

08 / CHOOSE THE NEXT EXAMPLE

Active learning

The model identifies examples for which labels would be most useful, and requests labels from a human or oracle. It aims to reduce labeling effort.

Example: ask an expert to label the medical images where the classifier is most uncertain.

TRADITIONAL ML VS DEEP LEARNINGFeature engineering vs representation learning

Traditional ML often relies more on humans designing useful input features, then applies methods such as linear models, decision trees, random forests or gradient boosting. Deep learning uses multilayer neural networks to learn hierarchical representations from data. The boundary is not absolute: deep learning is itself a family of machine-learning methods.

DISCRIMINATIVE VS GENERATIVEPredict a label vs model / create data

Discriminative models learn to distinguish classes or estimate a target, such as spam vs not spam. Generative models learn patterns in a data distribution and can create new samples, such as text, images or audio. Generative AI is an application area, not a separate learning paradigm.

IMPORTANT CONNECTIONS

How do the concepts fit together?

  • AI is the broad field; ML is an approach within AI that learns patterns from data.
  • Deep learning is a subset of ML based on neural networks with multiple layers.
  • Transformers are a neural-network architecture, not a learning paradigm.
  • Regression and classification are tasks; they are commonly solved with supervised learning.
  • Generative AI creates content. Autoregressive models, diffusion models, GANs and VAEs are different generative model families.
  • LLMs commonly use self-supervised next-token prediction during pretraining, then may be instruction-tuned and preference-aligned.

INTERVIEW QUESTION BANK

Machine Learning — questions & answers

Expandable interview questions covering definitions, comparisons, examples, trade-offs and LLM connections.

24 QUESTIONS
A · Learning paradigms
1. What are the main types of machine learning?

The common learning paradigms are supervised, unsupervised, semi-supervised, self-supervised and reinforcement learning. Other approaches such as transfer, online and active learning describe how knowledge is reused, how updates arrive, or how training examples are selected. These categories can overlap.

2. Explain supervised learning with an example.

The model trains on input-target pairs and learns to predict the target for unseen inputs. For example, train on house attributes paired with sale prices, then predict a price for a new house. Classification predicts categories; regression predicts continuous values.

3. Explain unsupervised learning with an example.

The model receives data without explicit target labels and tries to discover structure, such as clusters or lower-dimensional representations. For example, k-means can group customers by similar behavior. A discovered cluster is not automatically a meaningful business segment; interpretation is still needed.

4. What is the difference between supervised and unsupervised learning?

Supervised learning has target labels and optimizes predictions against them. Unsupervised learning has no explicit target labels and seeks patterns or structure. The distinction is about the training signal, not whether the data is structured or unstructured.

5. What is self-supervised learning? Is it supervised learning?

It derives targets automatically from the data, such as masking part of an input and predicting it, or predicting the next token. The optimization uses input-target pairs, but humans do not manually label each target. It is usually treated as its own paradigm because the supervision is generated from the data itself.

6. What is semi-supervised learning?

It combines a relatively small labeled dataset with a larger unlabeled dataset. Techniques include pseudo-labeling and consistency regularization. It helps when unlabeled data is plentiful but expert labels are costly; poor pseudo-labels can reinforce model mistakes.

7. What is reinforcement learning?

An agent observes a state, chooses an action, receives a reward and transitions to another state. It learns a policy to maximize expected cumulative reward. Unlike ordinary supervised learning, feedback is often delayed and depends on a sequence of actions.

8. What is the difference between supervised learning and reinforcement learning?

Supervised learning typically learns from fixed examples with known target answers. RL learns from interaction and reward feedback; the agent's actions affect which states and future data it sees. Rewards may be sparse or delayed, and the agent must balance exploration with exploitation.

9. What is transfer learning?

It starts from a model or representation learned on a source task and adapts it to a target task. It can reduce data and compute requirements, but transfer may fail when the source and target domains differ substantially.

10. What are online learning and active learning?

Online learning incrementally updates a model as new data arrives. Active learning chooses which examples should be labeled next, often prioritizing uncertain or informative samples. One concerns the update process; the other concerns data selection.

B · Tasks and model families
11. What is the difference between regression and classification?

Regression predicts a numeric quantity, such as delivery time or temperature. Classification predicts a discrete class, such as fraud/not fraud. Both are commonly supervised tasks; a classification model may output probabilities before choosing a class.

12. Is clustering the same as classification?

No. Classification assigns examples to predefined classes, usually using labeled training data. Clustering groups examples based on similarity without requiring predefined labels. Clusters need not correspond to ground-truth categories.

13. What is the difference between traditional ML and deep learning?

Traditional ML often depends on engineered features and methods such as linear models, trees and boosting. Deep learning uses multilayer neural networks that can learn representations from raw or lightly processed data. Deep learning typically needs more data and compute, but can perform especially well on complex inputs such as images, audio and language.

14. Is deep learning separate from machine learning?

No. Deep learning is a subset of machine learning. Machine learning includes many methods that are not deep neural networks, such as linear regression, decision trees and gradient-boosted trees.

15. What is the difference between discriminative and generative models?

Discriminative models learn a decision boundary or conditional relationship useful for predicting labels, often represented as P(y|x). Generative models learn a data distribution or joint structure, and can generate samples; some model P(x), others P(x,y). The distinction is about what is modeled and what the model can do.

16. Is generative AI a learning paradigm?

Not exactly. Generative AI describes systems that generate content. Those systems can be trained with different objectives and techniques, including self-supervised autoregressive training, diffusion objectives, or adversarial training in GANs.

17. Where do CNNs, RNNs and Transformers fit?

They are neural-network architectures used in deep learning. CNNs are effective at local spatial patterns, RNNs process sequences recurrently, and Transformers use attention to model relationships among sequence elements. They are not learning paradigms like supervised or reinforcement learning.

18. What are common generative model families?

Autoregressive models generate elements sequentially (for example, next-token LLMs); diffusion models iteratively denoise; GANs train a generator against a discriminator; VAEs learn a probabilistic latent-variable representation and decode samples from it. They differ in objective, sampling process and trade-offs.

C · LLM and practical interview follow-ups
19. How are LLMs trained, in terms of learning paradigms?

Many LLMs are pretrained with self-supervised objectives, commonly next-token prediction over large text corpora. They may then undergo supervised instruction fine-tuning and preference optimization or reinforcement-learning-based alignment. The exact pipeline varies by model.

20. Is next-token prediction supervised learning?

The training loss compares predictions with a target next token, so it has a supervised-style objective. But the targets are shifted from the original text automatically rather than manually annotated. That is why it is generally called self-supervised learning.

21. Can one model use multiple learning paradigms?

Yes. A system can be pretrained self-supervised, fine-tuned on labeled examples, and further optimized using preference feedback or RL. A game-playing system can combine supervised learning from expert demonstrations with RL from interaction. The paradigms describe different training stages or signals.

22. What is feature engineering, and why is it important?

Feature engineering transforms raw data into useful input variables using domain knowledge, such as extracting age from date of birth or aggregating a user's activity over 30 days. It can strongly improve traditional ML. Deep models can learn features, but still depend on sound data preparation and representation choices.

23. When would you choose a traditional ML model over deep learning?

For tabular data, modest datasets, tight latency or compute budgets, and problems where interpretability or simpler deployment matters, tree ensembles or linear models can be excellent choices. Choose based on validation performance, operational constraints and maintainability—not on the assumption that a larger neural network is always better.

24. How would you explain the types of ML in one minute?

Supervised learning learns from labeled answers; unsupervised learning finds structure without labels; self-supervised learning creates targets from the data; semi-supervised learning combines a small labeled set with a large unlabeled set; and reinforcement learning learns actions from rewards. Transfer learning reuses prior knowledge, online learning updates incrementally, and active learning selects which data should be labeled. Deep learning is a model family within ML, not another feedback paradigm.

Interview trap to avoid: don't present supervised, deep learning, generative AI, and Transformers as sibling categories. They describe different things: training signal, model family, application capability, and architecture.

CNN vs RNN vs LSTM vs GRU vs Transformer

Why architectures emerged, what problem each addresses, how they work, and where their trade-offs matter.

Covered in session
THE BIG PICTURE
CNN · Spatial patternsLocal filters learn visual featuresPixels → edges → textures → object patterns
RNN family · Sequence memoryProcess one step at a time, carry state forwardRNN → LSTM / GRU (gated memory)
Transformer · AttentionTokens directly relate to other tokensSelf-attention + feed-forward layers

This is not a strict lineage. CNNs target spatial patterns; recurrent networks target sequential information. LSTM and GRU refine recurrent memory; Transformers provide attention-based sequence modelling and are central to modern LLMs.

01 / SPATIAL DATA · VISION

CNN — Convolutional Neural Network

Problem: images are grids of pixels; meaningful objects are built from visual patterns.

How it works: small filters (kernels) slide across the image and detect local patterns. Early layers learn edges/corners, middle layers combine them into textures or shapes, deeper layers learn more task-specific patterns. Pooling or strided operations can reduce spatial resolution.

Example: identify pedestrians, cars, traffic signs, or classify a cat vs dog image.

Limitation: a basic CNN processes frames spatially but has no inherent memory of the order of video frames or earlier events.

02 / SEQUENTIAL DATA

RNN — Recurrent Neural Network

Problem: in text, audio and time series, order matters; the same items in a different order can mean something different.

How it works: each step consumes the current input and the previous hidden state, then produces a new hidden state. The state is a compact running context that gets passed to the next step.

Example: read “I am going to …” sequentially and use prior words to predict the next word.

Limitations: vanishing/exploding gradients can make long dependencies hard to learn; sequential steps limit parallelism during training.

03 / BETTER LONG-RANGE MEMORY

LSTM — Long Short-Term Memory

Problem: vanilla RNNs may lose useful information across long sequences.

How it works: adds a cell state (memory path) and gates that regulate information flow. Forget gate controls what to discard, input gate what to write, output gate what to expose in the hidden state.

Memory intuition: cell state carries longer-term information; hidden state represents the current step and is passed onward.

Trade-off: better control over memory, but more parameters/operations than a basic RNN and still sequential.

04 / SIMPLER GATED RECURRENCE

GRU — Gated Recurrent Unit

Motivation: provide gated memory with a simpler recurrent design.

How it works: update gate controls how much prior state to retain versus new information; reset gate controls how much old state influences candidate information. GRU does not have a separate cell state like LSTM.

Trade-off: often fewer parameters and can train faster, but it is not universally better; quality and speed depend on task, data and implementation.

05 / ATTENTION-BASED SEQUENCE MODELLING

Transformer

Problem: recurrent models must carry context step-by-step, which limits parallelism and makes distant relationships harder to learn efficiently.

How it works: token IDs are embedded, positional information is added, and self-attention lets each token compute contextual information from other tokens. Feed-forward layers refine representations; the stack repeats.

GPT-style output: predict a next-token distribution, select a token, append it, and repeat generation.

Strengths: parallelizable sequence processing during training, direct token-to-token relationships, and scaling. Limitations: attention can be costly for long contexts; high compute/memory needs; generation is still sequential token-by-token.

06 / TRANSFORMER INPUT → OUTPUT

What happens to a sentence?

1. Tokenize into token pieces and IDs.

2. Map IDs to learned embedding vectors.

3. Add or apply positional information so order is represented.

4. Attention uses Q (what to look for), K (what can be matched), and V (information to retrieve); layers combine contextual signals.

5. Feed-forward blocks transform representations. The final head produces logits over vocabulary tokens; softmax can turn logits into probabilities.

LSTM VS GRUMore explicit memory vs compact gating

LSTM uses a cell state plus forget, input and output gates. GRU uses update and reset gates and merges memory into its hidden state. GRU is simpler, but there is no universal winner—benchmark on the actual problem.

RNN FAMILY VS TRANSFORMERState passed forward vs attention across positions

RNN/LSTM/GRU carry information stepwise and are difficult to parallelize across time. Transformer self-attention computes token relationships across the sequence in parallel during training, at a memory/compute cost that can grow sharply with sequence length.

ARCHITECTURE CHOICE

Which would you use—and why?

  • CNN: image/spatial features, local patterns, vision pipelines.
  • RNN: sequence tasks where recurrence/state is useful; now often replaced in large-scale language modelling.
  • LSTM / GRU: recurrent sequence modelling when gated state and compact sequence processing are useful; consider simpler GRU vs richer LSTM empirically.
  • Transformer: language, multimodal and other sequence problems where attention, scale and parallel training are beneficial; weigh context-length compute and serving cost.

INTERVIEW QUESTION BANK

Neural architectures — questions & answers

Revision questions from basic intuition through architecture differences, attention, trade-offs and practical selection.

24 QUESTIONS
A · Foundations & CNNs
1. Why do neural-network architectures matter?

An architecture defines how information flows, what patterns the model can represent efficiently, and what assumptions it makes about the data. A convolution exploits local spatial structure; recurrence handles ordered sequences with state; attention explicitly relates elements. Architecture affects quality, compute, memory, latency and training behaviour.

2. What is a CNN, in simple terms?

A CNN applies learned filters across spatial data to detect patterns. The same filter is reused at different locations, helping recognize a feature regardless of where it appears. Multiple layers build increasingly complex features from local ones.

3. What is a convolutional filter/kernel?

A small matrix of learned weights slides across an input. At each location it combines nearby values to produce a feature-map value. During training, the weights are adjusted so useful patterns—such as edges or textures—are detected for the task.

4. Why do CNNs use pooling or stride?

Downsampling reduces spatial resolution and computation, and can make representations less sensitive to small shifts. It also discards information, so aggressive downsampling can hurt localization or detail-heavy tasks.

5. Can a CNN understand a video?

A frame-level CNN can extract visual features from individual frames. Temporal understanding requires modeling how frames relate over time—using a temporal module, 3D convolutions, recurrent layers, attention/Transformers, or other video architectures. A basic image CNN alone does not maintain frame history.

6. Why are CNNs useful for vision?

Images have local spatial structure: nearby pixels often combine into edges, textures and shapes. Convolution uses local receptive fields and weight sharing, reducing parameters relative to dense connections and learning reusable patterns across the image.

B · RNN, LSTM and GRU
7. Why was the RNN architecture introduced?

It provides a way to process ordered inputs while carrying a hidden state from one step to the next. The state summarizes previous information so the current output can depend on sequence history, unlike a plain feed-forward model applied independently to each item.

8. What is the hidden state of an RNN?

The hidden state is a learned vector updated at every time step from the current input and previous hidden state. It acts as a running summary of context. It is not a perfect transcript of the entire past; the model must compress relevant information into a fixed-size state.

9. Why do vanilla RNNs struggle with long dependencies?

During backpropagation through many time steps, gradients can shrink (vanish) or grow (explode), making long-range credit assignment difficult. The hidden state also has limited capacity to preserve information over a long sequence. Sequential processing makes parallelization across time difficult.

10. What problem does LSTM solve?

LSTM introduces a cell state and gates to control what information is forgotten, added and exposed. This provides a more deliberate path for carrying information over longer sequences and helps mitigate vanishing-gradient issues, although it does not eliminate all long-sequence challenges.

11. Explain the LSTM forget, input and output gates.

The forget gate controls how much prior cell-state information to retain; the input gate controls how much new candidate information to write; the output gate controls how much cell-state information contributes to the current hidden state. Gate values are typically learned through sigmoid activations.

12. What is the difference between cell state and hidden state in LSTM?

The cell state is the memory pathway designed to carry information across time. The hidden state is the exposed representation used for the current output and passed to the next time step. They interact but serve different roles.

13. What is a GRU, and why use it?

GRU is a gated recurrent architecture with update and reset gates. It combines memory and hidden representation rather than maintaining LSTM's separate cell state. It offers a simpler alternative that can be computationally efficient while still modeling sequential dependencies.

14. What do the GRU update and reset gates do?

The update gate controls how much of the previous state remains versus how much candidate information is incorporated. The reset gate controls how much prior state contributes when forming candidate information for the current step. Together they regulate memory flow.

15. Is GRU always better than LSTM?

No. GRU has a simpler design and may train or run faster; LSTM has a distinct cell state and more gates. Performance depends on dataset, sequence length, task, tuning and implementation. Compare both empirically if resources allow.

C · Transformer, attention and comparisons
16. What limitation of RNNs motivated Transformers?

RNN-family models process tokens sequentially and pass context through recurrent state, which limits parallelism and can make distant dependencies difficult. Transformers use attention to connect sequence positions directly and process positions in parallel during training (subject to masking and implementation).

17. What is self-attention?

Self-attention computes context-aware representations by letting each token score other tokens in the same sequence, then combine information from them. This allows a token's representation to incorporate relevant context from distant positions instead of relying only on a recurrent state chain.

18. Explain Query, Key and Value intuitively.

Query represents what this position is looking for; Key represents what each position offers for matching; Value is the information that gets combined when a position is attended to. Similarity between queries and keys produces attention weights, which weight the values.

19. Why does a Transformer need positional information?

Self-attention alone does not inherently encode sequence order. Positional encodings or position-dependent mechanisms let the model distinguish tokens and relationships based on their positions—for example, “dog bites man” from “man bites dog.”

20. What are the main steps in a GPT-style Transformer?

Tokenize text → map token IDs to embeddings → incorporate position information → apply stacked masked self-attention and feed-forward blocks with residual connections and normalization → project the final hidden state to vocabulary logits → choose the next token and repeat. GPT-style models use causal masking so a position cannot see future tokens during prediction.

21. How is a Transformer different from an RNN during training?

RNNs have a dependency from one time step to the next. Transformer layers can compute token representations across positions in parallel during training, making them more hardware-efficient at scale. Autoregressive Transformer inference still generates tokens sequentially, although each token's prompt processing uses attention.

22. Why can Transformer attention become expensive on long contexts?

Standard dense self-attention computes interactions among pairs of positions, so its attention computation and memory scale approximately quadratically with sequence length (O(n²)). Long-context methods optimize, approximate, restrict or restructure this computation, but long inputs remain an engineering cost.

23. Are CNN, RNN and Transformer mutually exclusive?

No. They are architectures and can be combined. For example, a CNN can extract frame features, then an RNN can model their temporal order; a Transformer can attend over CNN-derived features. The best choice depends on the data and problem.

24. What is the high-level evolution from CNN/RNN to Transformer?

CNNs efficiently exploit spatial structure, especially in vision. RNNs introduce stateful sequential processing. LSTM and GRU improve how recurrent models manage information over time. Transformers replace recurrence with attention-based sequence interactions, enabling more parallel training and scaling. This is a conceptual story, not a single linear replacement chain: CNNs remain useful in vision, and architecture choice depends on the task.

Interview trap: do not claim CNN evolved into RNN, or that Transformer is always superior. Explain what data structure the architecture exploits, what it enables, and what it costs.

STEP 01 / LINEAR PROJECTIONS

Create Q, K and V

Each token embedding is multiplied by three learned projection matrices:

Q = XWQ · K = XWK · V = XWV

With X = 6 × 8 and one toy head using dk = dv = 4, choose each projection matrix as 8 × 4. Q, K and V are then each 6 × 4.

STEP 02 / MATCHING

Compute QKᵀ—not QV

Q (6 × 4) multiplied by Kᵀ (4 × 6) produces a 6 × 6 score matrix. Every row is one query token; every column is one key token. The score at row i, column j represents how strongly token i's query matches token j's key.

STEP 03 / SCALE

Divide by √dk

Scale the raw scores by √4 = 2 in this toy example. Scaling keeps dot-product magnitudes from becoming too large as key/query dimensions grow, which helps softmax avoid overly saturated distributions and supports stable gradients.

S = QKᵀ / √dₖ

STEP 04 / SOFTMAX

Turn scores into attention weights

Apply softmax row-wise across the key positions. Each row becomes a probability distribution (sums to 1), expressing how much that query position attends to each token position. In GPT-like causal self-attention, a mask blocks future positions before softmax.

A = softmax(S + mask) (mask is optional for bidirectional attention; causal for decoder-only GPT-style models).

STEP 05 / AGGREGATE CONTENT

Multiply the weights by V

A (6 × 6) multiplied by V (6 × 4) gives Z (6 × 4). For each query token, its output is a weighted sum of Value vectors from the tokens it is allowed to see. Attention weights select/blend information; they are not the final contextual vector themselves.

Z = AV

STEP 06 / CONTEXTUAL OUTPUT

What does Z mean?

Z contains one context-aware output vector per token. A token's vector now mixes information from other positions according to attention. It is not one vector for the whole sentence—the output is still a sequence of 6 vectors (6 × 4 in this single-head toy example).

SINGLE-HEAD SELF-ATTENTION · FLOW

X (6 × 8) → learned WQ/WK/WV → Q, K, V (each 6 × 4) → QKᵀ (6 × 6) → divide by √dₖ → optional mask → row-wise softmax (A, 6 × 6) → A × V → Z (6 × 4 contextual vectors).

Self-attention means Q, K and V are projected from the same input sequence X. In cross-attention, Q comes from one sequence while K and V come from another.

MULTI-HEAD ATTENTION · EXAMPLE WITH 2 HEADS

Assume model width = 8 and 2 heads, each with head dimension 4. Each head has separate projection weights and independently runs the same attention pipeline over the sequence:

Head 1: Q₁, K₁, V₁ → scaled dot-product attention → Z₁ (6 × 4)
Head 2: Q₂, K₂, V₂ → scaled dot-product attention → Z₂ (6 × 4)

Concatenate the two outputs along the feature dimension: Concat(Z₁, Z₂) → 6 × 8. A final learned output projection WO (8 × 8 in this toy setup) mixes the concatenated head information and returns the sequence to model width 8.

Formula: MultiHead(Q,K,V) = Concat(head₁,…,headₕ)WO, where headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV).

Heads may learn different useful patterns, but we do not hard-code one head to “syntax” and another to “meaning.” Specialization is learned and can be distributed across heads.

KV CACHE / WHY

Why store Keys and Values?

In autoregressive decoding, the model generates one token at a time. Previous tokens' K and V for each layer are reused at future steps. Caching them avoids recalculating these projections and repeating attention work for earlier tokens at every generation step.

KV CACHE / NEXT TOKEN

What happens when a new token arrives?

At each layer, the new token's hidden state produces its Q, K and V. Append the new K/V to the layer's cache; the new Q attends to the cached K values (plus the new position, as allowed by causal masking), then combines the resulting weights with cached V values. The model still generates sequentially—KV cache makes each step cheaper.

KV CACHE · SIMPLE GENERATION FLOW

Prompt prefill: process prompt tokens → compute each layer's K/V → store cache.

Next-token step: process newest token → compute its Q/K/V → append K/V to cache → Q attends over cached K → weights combine cached V → output predicts next token.

Trade-off: less recomputation and faster decoding, but the cache consumes memory and grows with batch size, layers, sequence length, and KV-head dimensions. Long contexts can make KV-cache memory a significant inference cost.

16 QUESTIONS
A · Self-attention mechanics
1. Why do we compute QKᵀ instead of QVᵀ?

Q and K are the learned representations used to calculate compatibility/scores. V contains the content to be aggregated after those scores become attention weights. Mixing V into the score calculation would change the mechanism's roles.

2. What shape is the attention score matrix for n tokens?

With Q and K shaped n × dₖ, QKᵀ has shape n × n: each query position is scored against every key position. With causal masking, future-position scores are set to an effectively negative infinity before softmax so their weights become zero.

3. Why divide by √dₖ?

As dₖ grows, dot products can grow in magnitude. Large logits can push softmax into saturated regions with very small gradients. Scaling by √dₖ controls the magnitude of scores and helps training stability.

4. What exactly does softmax do here?

For each query row, it converts scores across key positions into nonnegative weights that sum to one. Those weights describe how the query distributes attention over available tokens; they are then used to weight V, not Q or K.

5. Is the attention output a single vector for the sentence?

No. Standard self-attention returns one contextual output vector per input position. The output is a matrix of sequence length × value dimension (per head), not one pooled sentence vector.

6. Why is it called self-attention?

Because queries, keys, and values are derived from the same input sequence. Cross-attention uses queries from one sequence and keys/values from another.

7. Why is a causal mask used in GPT-style models?

To prevent a position from attending to future tokens it should not see when predicting the next token. Masked future scores become zero after softmax, preserving autoregressive training and generation.

B · Multi-head attention
8. Why use multiple heads instead of one attention head?

Multiple heads use different learned projections, enabling the model to represent and attend through multiple feature subspaces/relationships in parallel. Their outputs are concatenated and transformed by a learned output projection.

9. Do heads have predefined jobs such as syntax, coreference or semantics?

No. These are illustrative patterns that some heads may learn. The model does not assign those jobs explicitly, and attention-head behavior is not guaranteed to be cleanly interpretable or one-head-one-function.

10. What happens after each head computes attention?

The per-head outputs are concatenated along the feature dimension, then multiplied by a learned output projection Wᴼ. This mixes the head outputs and typically returns to the model's hidden width.

11. In a model with width 8 and 2 heads of width 4, what are the shapes?

For 6 tokens: each head output is 6 × 4; concatenation is 6 × 8; the final projection Wᴼ (8 × 8 in this toy example) keeps the output 6 × 8. Real models use different dimensions and head counts.

C · KV cache & inference
12. What exactly is cached in the KV cache?

Key and Value tensors for prior tokens, typically stored per Transformer layer (and with the architecture's KV-head layout). They are reused in later autoregressive steps so prior token K/V projections do not need to be recomputed.

13. Are Query vectors cached?

Typically the standard KV cache stores K and V, not Q. The query for the current decoding position is computed when that position is processed and used to attend over the available cached keys.

14. Does KV cache make generation parallel?

No. Autoregressive generation still predicts one token at a time because each next token depends on the previous generated token. KV cache reduces redundant computation within each step; it does not remove the sequential dependency between generated tokens.

15. What is the trade-off of KV cache?

It reduces recomputation and improves decode efficiency, but consumes memory proportional to cached sequence length, batch, layers, and KV dimensions. Longer contexts and larger batches increase memory usage.

16. Does the cache hold only one layer's K/V?

No. Each Transformer layer maintains its own cached K/V states for past positions. A complete model cache contains the per-layer caches, with layout depending on the implementation and architecture.

Interview traps: QKᵀ produces scores; softmax produces attention weights; AV produces contextual outputs. KV cache stores past Keys and Values (not attention scores and not typically Queries). Multi-head attention concatenates head outputs and applies Wᴼ.
