MODULE 01 · QUICK REVISION

Tokenization

How raw text becomes the numeric sequence an LLM can process.

In progress
THE PIPELINE
INPUT“Hello world!”
→
TOKENIZERSplit into pieces
→
TOKEN IDs[15496, 995, 0]

Text → token pieces → integer IDs → model embeddings. The model consumes vectors, not words directly.

01 / DEFINITION

What is a token?

A token is a unit of text chosen by a tokenizer. It can be a whole word, part of a word, punctuation, whitespace, or a byte-level piece.

02 / DON'T CONFUSE

Token ≠ ID ≠ embedding

  • Token: text piece, e.g. cat
  • Token ID: integer assigned to that piece
  • Embedding: learned vector looked up using the ID
03 / WHY SUBWORDS

Why not one token per word?

A word-only vocabulary becomes huge and struggles with unseen words. Character-only splitting creates long sequences. Subwords balance vocabulary size and sequence length.

04 / BPE

Byte Pair Encoding

Repeatedly merge frequent adjacent units into a larger unit during tokenizer training.

l+o→lo→low

Illustrative merge sequence, not a universal tokenizer vocabulary.

VOCABULARYA finite lookup table

Each token piece has an integer ID. IDs are labels, not semantic scores; ID 500 is not “more meaningful” than ID 20.

SPECIAL TOKENSStructure & control markers

They can mark message boundaries, end-of-sequence, padding, unknown input, or roles in a chat format.

INTERVIEW CHECK

Can you explain these without mixing them up?

  • Why can the same sentence have different token counts in different models?
  • Why does tokenization affect context limits and inference cost?
  • Why can emojis, code, whitespace, and Hindi split into surprising pieces?
  • What is the difference between a tokenizer vocabulary and an embedding table?
